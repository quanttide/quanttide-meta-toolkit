# 路线图

## 现状（0.2.x）

本库是元工程领域（`meta-engineering`）的 Python SDK，当前提供归纳特征：`storage`（跨平台目录，XDG 规范）与 `fields`（8 个标准字段）。

## v0.3.0：对齐元工程建模升级（破坏性）

元工程建模近期完成结构性升级，v0.3.0 要做的是对齐这套建模本身，而不是继续扩充归纳特征。升级要点的事实源在元工程手册与档案仓，本库只引用、不重述：

- 起点是主数据：先确立系统的唯一事实源——身份、权威源与多视图——再谈其余；
- 三层结构：主数据（实体层）→ 本体层 → 范畴层；范畴论只在范畴层使用，用于跨形态的函子与收敛判定；
- 表达为骨架（Spec）× 血肉（Impl）：骨架定义数据模式、状态空间与合法转移，血肉是同一副骨架上的实现；
- 元工程的手艺是把需求分解进标准化体系：哪些用已有领域解决，哪些为客户新建领域。

### 定位变更

从「归纳特征集合」变为「元工程建模的 Python 实现」：库的对象由工具函数变为模型与结构——主数据的身份与权威源、骨架与血肉的对应、形态之间的映射与收敛。

### 破坏性

v0.3.0 是一次彻底升级定位的破坏性更新：0.2.x 的公开 API（`LocalStorage` 与 8 个标准字段）在 0.3.0 中不作兼容承诺，可能被重写、改名或移出本库。使用方升级前先读本文件与随版本发布的迁移说明。

### 参考

- [元工程手册](https://github.com/quanttide/quanttide-handbook-of-meta-engineering)：主数据、需求分解与领域划分、范畴论的适用边界
- [元工程档案](https://github.com/quanttide/quanttide-archive-of-meta-engineering)：建模思路（骨架 × 血肉）

## 版本策略

0.x 为验证期：破坏性变更由次版本号承载（0.2 → 0.3），补丁号只做修复。
